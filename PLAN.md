# Learn With Writing — Implementation Plan

Type along with a YouTube video. Paste a link, the video is embedded, its transcript is split into
timed segments, and the current segment is shown under the player. You type it while the video plays.
If the segment ends before you finish, the video pauses and waits; once you finish, it plays again.

---

## 1. Tech stack

| Concern | Choice | Why |
|---|---|---|
| App framework | **Next.js (App Router) + TypeScript** | One project for UI and the small server part the transcript needs |
| Styling | **Tailwind CSS** | Fast to build the minimal, typing-focused UI |
| Video | **YouTube IFrame Player API** | Official way to embed and control playback (`playVideo`, `pauseVideo`, `seekTo`, `getCurrentTime`, `setPlaybackRate`) |
| Transcript | **`youtubei.js`** in a Next.js API route (server side) | Browsers can't fetch YouTube captions directly (CORS). It is actively maintained and returns timed captions for most public videos |
| State | **Zustand** (or `useReducer`) | The typing engine and the player sync share state; keep it in one small store |
| Persistence | `localStorage` | Recent videos, progress per video, settings. No database or accounts in v1 |
| Tests | **Vitest** (logic), **Playwright** (one end-to-end smoke test) | The segmenter and the matcher hold most of the logic and are easy to unit test |

No database, no login, no paid services for the first version.

---

## 2. How it works

```
 Paste URL ─► parse videoId ─► GET /api/transcript?v=ID ─► raw captions
                                                              │
                                                              ▼
                                                   segmenter (merge/split)
                                                              │
                                                              ▼
 YouTube IFrame player ◄──── sync loop (every ~100 ms) ────► segments[]
        ▲   │                     │                            │
        │   └── currentTime ──────┘                            ▼
        │                                               typing engine
        └──── play / pause ◄──── "segment done?" ◄───── (keystrokes)
```

### The core rule (sync loop)

Every ~100 ms (via `requestAnimationFrame` or `setInterval`) read `player.getCurrentTime()`:

1. **Video reaches `segment.end` and the segment is not finished** → `pauseVideo()`, set `pausedByApp = true`.
2. **User finishes the segment**:
   - if `pausedByApp` → `playVideo()`, clear the flag;
   - move to the next segment.
3. **User finishes early** (video still inside the segment) → mark it done, show the next segment
   faded/"up next", and start it when the video reaches its start time (configurable: allow typing ahead).
4. **User seeks / clicks prev-next** → find the segment for the new time (binary search on `start`),
   reset typing for that segment.
5. **User pauses manually** → respect it; never auto-play a video the user paused themselves.

> **Learned in M1:** browsers (Safari strictly, Chrome depending on site engagement) can block
> unmuted `playVideo()` sent from outside the YouTube iframe until the user has played the video
> themselves. A blocked player can even report `PLAYING` with the time frozen. So the first start
> of each video must be the user's own click on the video; after that, play/pause from code works.

## 3. Transcript fetching and segmentation

### 3.1 Fetching (`/api/transcript`)

- Input: `videoId`, optional `lang`.
- Output: `{ videoId, title, language, isAutoGenerated, availableLanguages[], cues: [{ start, end, text }] }`.
- Prefer a manual (human) track in the requested language; fall back to auto-generated.
- Cache results in memory (and later on disk) by `videoId+lang`, since captions don't change.
- Clear errors for: no captions, private/age-restricted video, fetch blocked.

> **Risk:** YouTube has no official API for reading captions of videos you don't own, so every
> library relies on internal endpoints that can break or be rate-limited (especially from cloud
> server IPs). Mitigations: keep the fetcher behind one interface (`TranscriptProvider`), so we can
> swap in `yt-dlp` or a Python `youtube-transcript-api` microservice; run locally first; also allow
> **uploading an `.srt` / `.vtt` file** as a manual fallback.

> **Learned in M2:** `youtubei.js` `getBasicInfo` with the `WEB` client returns caption tracks
> (`IOS` as fallback); `getInfo` and the transcript panel endpoint failed. Captions are then
> downloaded from the track URL with `fmt=json3`. Auto-generated tracks carry per-word offsets,
> which the parser uses for word-level timing.

> **Learned in M5:** after many requests in a short time (e.g. repeated reloads while developing,
> which also clear the in-memory cache on every dev-server restart), YouTube answers caption
> downloads with **429 Too Many Requests** for a while. The app then says so and offers the
> `.srt` / `.vtt` upload. A persistent (on-disk) cache would reduce how often this happens.

### 3.2 Segmenter (pure function, unit-tested)

Raw cues are messy, especially auto captions (short overlapping fragments, no punctuation). Turn them
into typable segments:

- Decode HTML entities, normalize whitespace, fix overlapping times (`end = min(end, next.start)`).
- Drop non-speech cues: `[Music]`, `[Applause]`, `♪ … ♪`.
- **Merge** cues until a sentence end (`. ? !`) or a limit is hit: ~4–10 s or ~15–20 words.
- **Split** very long cues at commas or at the word limit, sharing time proportionally by length.
- Each segment gets `{ id, start, end, text, tokens[] }`.

### 3.3 Tokens

Split each segment into tokens:
- **word tokens** — the user must type these;
- **punctuation tokens** — shown automatically, not typed (setting: "type punctuation too").

## 4. Typing engine

### 4.1 Matching rules (pure function, unit-tested)

Normalize both sides before comparing:
- lowercase (setting: case-sensitive);
- straight vs curly quotes/apostrophes (`'` = `’`), dashes;
- accents optional (setting);
- numbers: accept "5" for "five" later (v2).

### 4.2 Input model

- One hidden `<input>` that always keeps focus (re-focus on click/blur). This also works with
  mobile keyboards and IME, and stops the YouTube iframe from catching key presses.
- Per-character state for the current word: `pending | correct | wrong`.
- **Space / Enter** moves to the next word (option: only when the word is correct, or auto-advance
  as soon as the word matches).
- **Backspace** edits the current word; can go back into the previous word.
- Wrong letters shown in red; finished words in the "done" color (like the screenshot).

### 4.3 Display modes

- **Show** — full sentence visible, type over it.
- **Fill / dictation** — some or all words hidden as `••••` (as in vocatype), you type what you hear.
  Difficulty: hide 0% / 30% / 60% / 100% of words.

### 4.4 Shortcuts

| Key | Action |
|---|---|
| `Ctrl+R` / `⌥R` | Replay current segment |
| `Ctrl+←` / `Ctrl+→` | Previous / next segment |
| `Tab` | Hint: reveal the next letter (Ctrl+H opens history in some browsers) |
| `Ctrl+Space` | Play / pause |
| `Ctrl+↑` / `Ctrl+↓` | Playback speed up / down |

(Avoid plain keys, since they are typing input.)

## 5. UI

Single page, centered, minimal (similar to the vocatype screenshot):

1. **Home** — URL input + recent videos list (thumbnail, title, progress %).
2. **Practice view**
   - YouTube player on top.
   - Progress bar: `segment 4 / 128` + time.
   - Control row: prev · replay · next · hint · speed · fullscreen.
   - **Current segment** in a large monospace font, with typed / current / remaining styling.
   - Small "up next" line.
   - Bottom toolbar: mode (show/fill), difficulty, case, punctuation, language.
3. **Session summary** at the end — WPM, accuracy, time, most mistyped words.

## 7. Milestones

Each step ends with something you can run and try.

### M1 — Project setup + player (≈0.5 day)
- Next.js + TS + Tailwind + Vitest setup.
- `parseUrl` (with tests) for all YouTube URL formats.
- Embedded player wrapper using the IFrame API; paste a link → video plays.

### M2 — Transcript (≈1 day)
- `/api/transcript` with `youtubei.js`, language choice, caching, error states.
- Segmenter + tests using real caption samples (manual and auto-generated).
- Debug view: list of segments with timestamps, click to seek.

### M3 — Typing engine (≈1–1.5 days)
- Tokenizer, matcher, engine reducer — all with unit tests.
- `TypingArea` with the hidden input, per-letter colors, backspace, auto-shown punctuation.

### M4 — Sync: pause / resume (≈1 day) — *the core feature*
- `usePlayerSync`: pause at segment end, resume on completion, typing ahead, seek handling,
  respect manual pause.
- Controls: replay, prev/next, speed.
- **This is the first fully usable version.**

### M5 — Learning features (≈1–2 days)
- Fill/dictation mode with difficulty levels, hints.
- WPM, accuracy, session summary.
- Save progress and recent videos in `localStorage`; resume where you left off.
- `.srt` / `.vtt` upload fallback.

### M6 — Polish (≈1 day)
- Shortcuts, settings panel, dark mode, responsive layout.
- Playwright smoke test: paste URL → type first segment → video resumes.
- Error screens: embedding disabled (player errors 101/150), no captions, invalid URL.

### Later (v2 ideas)
- Translation line under each segment (like vocatype).
- Review list of mistyped words / spaced repetition.
- Accounts + sync, shared video playlists.
- Speech-to-text (e.g. Whisper) for videos without captions.

## 8. Edge cases to handle

- Videos with embedding disabled → show a clear message.
- No captions in any language → offer `.srt` / `.vtt` upload.
- Gaps between segments (silence/music) → video keeps playing, show "up next".
- Very fast speech → long segments get split; user can lower playback speed.
- Ads (non-Premium users) → `getCurrentTime` stays on the video timeline, but the sync loop should
  ignore time while the player state is not `PLAYING`.
- Contractions and symbols in captions: `don't`, `$5`, `%`, `&`.
- Tab hidden → `requestAnimationFrame` stops; use `setInterval` as a backup, or pause when hidden.

## 9. Decisions to confirm before starting

1. **Stack** — Next.js full-stack OK, or do you prefer a Vite SPA + separate backend (e.g. Python
   FastAPI with `youtube-transcript-api`)?
2. **Typing strictness** — must every word be correct before moving on, or allow mistakes and just
   count them?
3. **Punctuation** — auto-filled (recommended) or typed?
4. **Typing ahead** — when you finish early, wait for the video, or let you start the next segment right away?
5. **Target languages** — English only at first, or any caption language from day one?
